# Known failing / vacuous gates.
#
# One gate ID per line. '#' starts a comment. sim/gate.py tolerates exactly
# these and blocks on anything else.
#
# This list is DEBT, not permission. A gate belongs here only with a written
# reason and only while someone intends to fix it. Adding a line here to make
# a red suite go green is the same offence as loosening a threshold.
#
# Baseline 2026-08-30, after M1 and M4B were FIXED:
# 25 gates, 4 FAIL, 0 VACUOUS, 21 pass.  Verified by a --tier full run.
#
# M1 and M4B were removed from this file on 30 August 2026 because they were
# repaired, not tolerated. M1 now runs its mutant at cap_override=2, so the
# attempt-cap counter is exercised instead of never binding. The `pending` and
# `represent` mutants no longer increment the counters they are graded on --
# they create illegal state and the harness's own independent checks catch it,
# which is what CLAUDE.md rule 1a requires. Both Stage 0 rules that previously
# had NO working test in sim/ now have one.
#
# The four that remain are findings, not debt: two calibration gates that fail
# on monotonicity for structural reasons no parameter can fix, one retired
# architecture kept red on purpose, and one negative control that turned out
# not to be neutral.
#
# Every figure quoted in the reasons below is from a --tier full run on
# 28 August 2026. They were stale once: this file carried S2b at -14.51,
# S2c at +24.04, S2_LEGACY at -0.40 and S1_PD at ECE 0.040, none of which
# the suite produces. If you change anything, re-run the suite and update
# these numbers in the same commit -- a reason file that disagrees with the
# gate it explains is worse than no reason file.

S1
# belief calibration: ECE<0.10 and monotone.  Currently ECE=0.091, monotone=False.
#
# THE 0.10 ECE THRESHOLD WAS DECLARED IN docs/05_TEST_DESIGN.md BEFORE ANY
# RESULTS WERE SEEN. IT MUST NOT BE LOOSENED. Note that ECE is already inside

S2b
# "placebo_pd is neutral vs own_pd".  Currently -14.09 pts (+/-2.09). NOT neutral.
#
# This is a finding about the experiment design, not a code defect, and it is
# the most important thing the 27 August rebuild produced.
#
# solo_placebo does not inject NEUTRAL extra update events. It injects WRONG
# ones -- outcomes computed against a different customer's balance
# (sim/harness.py:312). Feeding a belief actively misleading observations is
# worse than feeding it nothing, so the placebo arm is damaged rather than
# merely uninformative. Predicted in advance (NOTES.md pre-registration).
#
# Why it matters: S2c (real - placebo) is algebraically S2a + |S2b|, an
# identity for paired means, not an independent measurement. 60% of the
# +23.62 headline is placebo damage. docs/02_RESULTS.md used to present that
# number as "the strongest evidence we have" that pooling is information.
# It is not. The honest moat number is S2a, +9.53 pts (+/-1.81).
#
# Fixing this means building a control that matches the UPDATE COUNT without
# supplying wrong information -- e.g. label-shuffled observations with the
# matched base rate -- not relaxing the neutrality threshold. Left failing on
# purpose so the confound stays visible.

S2_LEGACY

S1_PD
# "SHIPPING belief calibration: ECE<0.10 and monotone". ECE=0.026, monotone=False.
#
# ADDED 2026-08-28, and the reason it exists is the finding.
#
# S1 runs `portfolio`. `portfolio` does not end in "_pd", so it carries
# w3.Belief -- the POINT-ESTIMATE payday filter. The policy this project
# recommends is `solo_shared_pd`, which carries w3.BeliefPD. So for the entire
# life of the project the calibration gate has been measuring a filter that is
# not the product, and every conclusion drawn from S1 about "the belief
# filter" was about the wrong object.
#
# S1 was NOT repointed. It is a pre-registered gate whose threshold was
# declared in docs/05_TEST_DESIGN.md before any result was seen, and quietly
# aiming it at a different policy would be indistinguishable from moving a
# test until it says something else. S1_PD is an ADDITION with the IDENTICAL
# threshold, on the real filter.
#
# It fails, on the monotonicity half, exactly as predicted in advance (the
# pre-registration guessed ECE 0.04-0.07 and "still fails on monotonicity",
# at ~60% confidence).
#
# TWO DIFFERENT ECE NUMBERS EXIST FOR THIS FILTER AND THEY ARE NOT THE SAME
# MEASUREMENT. This gate reports ECE=0.026 on populations Pc0-Pc2 (n=120,
# pop seeds 300-302, run seeds 800-802). sim/fair_audit.py reports 0.059
# shipped -> 0.040 fitted on DIFFERENT populations (n=100, pop seeds
# 700-702, run seeds 1600-1602). This file used to quote fair_audit's 0.040
# as if it were the gate's. Quote 0.026 for S1_PD and name fair_audit when
# quoting 0.040. Fitting improved ECE on both and made neither monotone.
#
# The remaining break is in the mid-range, and the plausible causes
# are the two things the fit does not touch: the filter does not model the
# balance floor at zero, and it approximates the world's hourly U(0.4,1.6)
# spend jitter with a fixed 3-tap kernel.
#
# Do NOT loosen the 0.10 bound; ECE is already well inside it. The gate fails
# on monotonicity and raising the ECE bound would only hide which half is
# broken.
